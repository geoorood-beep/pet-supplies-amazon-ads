# 盈利型自动瀑布流

备案日期：2026-11-14

来源：2026-11-14 通话记录中的通用五步。该记录写明来源是新版导图「盈利型广告放量 → AUTO瀑布流广告」和总纲 §12.1。

文件里没有针对具体品类或站点的版本。下面是通用流程，不另配品类参数。

「提降」在本页指动态竞价里的「提高和降低」。总纲把它和位置溢价分开计算。本流程没有写具体的提降比例。

## 起始状态

有一条盈利型 AUTO 广告，能持续花费，ACOS 在目标范围 ±20% 以内。

这句话是 2026-11-14 记录里的起始条件。总纲第十四章仍把「盈利型广告的利润或 ACOS 标准」列为待补充规则，补充确认前不能把这句话自动执行成全类目停开线。

## 五步

### 1. 搭测试框架

用老活动，放入所有变体，竞价策略用「提降」。AUTO 起手竞价约 `0.9x`（示例，按变量处理）。紧密、宽泛、同类、关联四个定位组都开。

### 2. 定位测试（A0）

分别比较四个定位组的花费、订单、CPA/ACOS 和搜索词偏移，关闭或拆出持续表现差的定位组。

进入下一步的条件：至少找到一个能持续花费的有效定位。

### 3. 盈利基准层（A1）

保留有效定位，建立第一条稳定盈利的活动。

进入下一步的条件：能持续花费，且在目标利润范围内。

### 4. 低 Bid 承接层（A2、A3）

把有效定位拆成竞价更低的新活动，承接剩余的低价流量。每加一层，都要先保证上一层能花费、能盈利、仍有增量空间。每层单独记录重叠、预算和利润。

层数、Bid 差值和预算都没有定，按实际数据决定。

### 5. 停止扩层（A4）

出现数据拆散、内部竞争或利润恶化时，不再新增活动，把无量层合并，把亏损层关闭。

## 提降在这条流程里的两个用法

1. 搭建时直接选「提降」。这是 2026-11-14 明确采用的新版做法。
2. 遇到花费瓶颈时，改为提降或回到老活动。

这个流程里没有写具体的提降比例。

## 与总纲 §12.1 的对应

总纲 §12.1 用 A0–A4 描述同一条顺序：先有一条能持续花费、且 ACOS/CPA 落在目标范围内的自动广告，再向下扩展；定位测试之后保留有效定位，再逐层降低 Bid；上一层不能花费、不能盈利或没有增量空间时，不加下一层。示例起点写的是可以从 `0.9x` 或其他接近基准的竞价开始。
